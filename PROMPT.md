# Локальный веб-инструмент для маркетинга: поиск лидов в 2ГИС по любой сфере и выгрузка в папки на компьютер

## Источник кода — только эта папка
Работай только с кодом в текущей папке (сбор данных и пагинация уже починены, есть режим leads). Не подтягивай сторонний код парсеров. Установка — только `pip install -e .` из этой папки в существующий .venv (Python 3.13, нужен Google Chrome).

## Что уже есть (использовать, не переписывать)
- CLI `leadbombing-cli -i <URL поиска 2ГИС>... -o <путь> -f {csv,xlsx,json,html,leads}`. URL: https://2gis.ru/<город>/search/<запрос>; несколько -i за раз.
- Веб-дашборд `leadbombing/web` (create_app, run_server, ParseJob, History) — запускается, если CLI вызван без аргументов. Изучи его первым: новый UI строить на нём, а не с нуля.
- Как парсер берёт данные (2ГИС менял сайт, всё ниже уже починено — не ломать):
  - выдача: страницы поиска; переход по страницам — навигацией по URL `/page/N` (клик в SPA список не обновляет);
  - фирма: в той же вкладке Chrome синхронный XHR на `/firm/<id>` и разбор серверного `window.initialState` → `data.entity.profile[<id>].data` (контакты, график, атрибуты, рубрики, org.branch_count, external_content.main_photo_url). Метод `MainParser._fetch_state(path, js_expr)`;
  - цены: `/firm/<id>/tab/prices` → `data.market` (products, offers.price_value: fixed / from / range.min, offersSearch…updated_at);
  - фото: `main_photo_url` скачивается обычным HTTP в `images/hero.jpg`;
  - 403/429/страница без initialState = капча или блок → прогон останавливается с сообщением (ParserException). Ошибка на одной фирме прогон не останавливает.
- Режим `-f leads` (`leadbombing/leads/`: text.py — телефоны/транслит/slug; build.py — залы, business.json, лид, строка outreach; writer.py — фильтры, слияние, отчёт) пишет базу:
  `<папка>/leads.json`, `<папка>/outreach.csv` (UTF-8 BOM), `<папка>/tenants/<slug>/business.json` + `images/hero.jpg`.
  Повторный запуск дописывает без дублей (ключ — id 2ГИС), известные пропускает (`--writer.refresh yes` — обновить), не затирает «Статус» и «Руководитель».
  «Писать сюда»: WhatsApp на мобильный → Telegram → ВК → мобильный → городской.
  Сейчас режим заточен под бани: рубрика «Бани и сауны», город Москва, исключения (фитнес/отели/бассейны/термы, сети ≥5 филиалов), правила «залов» в ценах, шаблоны крючка и сообщения.
- Проверки: `pytest tests/` (tests/test_leads.py); схема демо — `node --experimental-strip-types ../bani-leads/check.ts <папка>` (схема ../bani-pwa/src/shared/business-schema.ts).

## Жёсткое требование: форматы экспорта не меняются
CSV (`-f csv`, в т.ч. `--writer.csv.clean`), leads.json, outreach.csv (те же колонки и порядок: Баня, Демо (slug), Писать сюда, Канал, Телефон основной, Телефоны доп., Telegram, Email, Руководитель, Юрлицо, Адрес, Залы, Крючок, Сообщение, Статус, 2ГИС), business.json и раскладка папок остаются полностью совместимыми с текущими. UI только запускает парсер и читает эти файлы. Новые поля — только с моего согласия.

## Задача (MVP)
1. Форма поиска: ключевые слова (свободный текст → URL поиска 2ГИС); города — чекбоксами (slug городов 2ГИС: moscow, spb, …; список в конфиге); сфера — пресет из списка популярных или «любая»; лимит записей; папка выгрузки (по умолчанию `~/leads/<сфера>/`). Кнопка «Искать».
2. Прогон в фоне через существующий ParseJob; в UI — прогресс, итог (собрано / отсеяно по причинам) и понятная ошибка при блокировке.
3. Список лидов: компактная таблица (название, город/район, рейтинг, канал «Писать сюда», есть ли фото). Клик — карточка: hero-фото, все контакты, часы, адрес, цены/залы, крючок, готовое сообщение (кнопка «копировать»), ссылка на 2ГИС, кнопка «открыть папку».
4. Любая сфера: вынести всё «банное» из leads/build.py и leads/writer.py в пресет сферы (конфиг-файл), не меняя формат вывода: рубрики 2ГИС, слова-исключения, порог сети, слова для «залов/услуг», заглушка и цена по умолчанию, шаблоны крючка и сообщения; фильтр города — из выбранных городов (сейчас захардкожена Москва).
   Пресет «бани» должен давать тот же результат, что сейчас (сверить с ~/development/bani-leads-parcer/run-test).
   Для сфер без пресета — обычный CSV-режим (он работает для любого бизнеса). Демо business.json осмыслен только для почасовой аренды (бани, лофты, караоке и т.п.).

## Работа без ИИ
Инструмент работает полностью локально и без ИИ: никаких вызовов Claude/OpenAI/других LLM и внешних сервисов в рантайме — только Python, Chrome и 2ГИС. Крючок и сообщение — по шаблонам из пресета сферы, не генерируются моделью.
Запуск одной командой (например `leadbombing`), после которой UI открывается на http://localhost:<порт>. В README — короткая инструкция для маркетолога: установка с нуля (Python, Chrome, .venv, pip install -e .), запуск, где искать результаты.

## Не делать в MVP
- PWA и офлайн: нужен локальный Chrome и Python — достаточно локального веб-интерфейса.
- Авторизацию, мультипользовательность, облако, БД (источник правды — файлы).
- Новые источники данных (другие API, закрытые эндпоинты 2ГИС, сторонние сайты), обход капчи.
- Переписывание рабочих частей парсера.

## Порядок работы
1. ДО составления плана: изучи leadbombing/web (на чём он сделан) и предложи 2–3 варианта библиотек для UI и анимаций с плюсами и минусами (учти: локальный инструмент, минимум сборки, совместимость с текущим дашбордом). Остановись и жди моего выбора.
2. После выбора — план: что берём из leadbombing/web, какие правки в leads/, формат пресета сферы, экраны. Жди подтверждения.
3. Минимальная версия, тесты (pytest + check.ts на пресете «бани»).
4. Проверка готовности: без каких-либо внешних сервисов, кроме 2ГИС, инструмент запускается на localhost и проходит путь от формы поиска до папки с файлами.
5. Короткий отчёт: что сделано, что не проверено, риски.
